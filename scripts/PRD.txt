# Overview  
LifeHub is a real-time activity logging system designed for fitness enthusiasts and developers who want to track workouts and other activities efficiently. It provides a REST API (built with NestJS) for logging activities, streams these logs into Kafka for scalable processing, and persists them into Notion for easy tracking and visualization. LifeHub solves the problem of fragmented activity tracking by integrating modern event streaming and a popular productivity tool (Notion), making logs accessible and actionable.

# Core Features  
- **Workout Logging API**  
  - Provides a RESTful endpoint to log workouts (type, sets, reps, weight).
  - Ensures input validation and error handling.
  - Streams logs to Kafka for decoupled processing.
  - Important for real-time, reliable data capture and extensibility.

- **Kafka Integration**  
  - Uses Kafka as the message broker between the API and consumers.
  - Enables scalable, decoupled, and reliable log processing.
  - Docker Compose setup for local development.

- **Notion Consumer**  
  - Node.js service that consumes workout logs from Kafka.
  - Validates and persists logs into a Notion database.
  - Handles Notion API integration, error handling, and logging.

- **Developer Experience**  
  - .env.example files and clear setup instructions for both services.
  - Sample curl requests and end-to-end test guidance.
  - Comprehensive documentation for setup, usage, and architecture.

# User Experience  
- **User Personas**: 
  - Fitness enthusiasts who want to log and visualize workouts in Notion.
  - Developers seeking a template for event-driven logging systems.
- **Key User Flows**:
  1. User sends a workout log via the API.
  2. Log is validated and streamed to Kafka.
  3. Notion consumer picks up the log and adds it to the Notion database.
  4. User sees the new entry in Notion.
- **UI/UX Considerations**:
  - No frontend in MVP; user interacts via API and Notion.
  - Clear error messages and documentation for API usage.

# Technical Architecture  
- **System Components**:
  - API Gateway (NestJS): Exposes REST endpoint, produces to Kafka.
  - Kafka (Docker Compose): Message broker for logs.
  - Notion Consumer (Node.js): Consumes from Kafka, writes to Notion.
- **Data Models**:
  - WorkoutLog: { type: string, sets: number, reps: number, weight: number }
- **APIs and Integrations**:
  - REST API: POST /log/workout
  - Kafka: workout-logs topic
  - Notion API: Insert row into database
- **Infrastructure Requirements**:
  - Docker + Docker Compose
  - Node.js (>=16)
  - Notion Integration Token & Database ID

# Risks and Mitigations  
- **Kafka Complexity**: Use Docker Compose for local setup; provide clear documentation.
- **Notion API Limits**: Implement error handling and respect rate limits.
- **Data Loss**: Use at-least-once delivery for MVP; consider idempotency for Notion writes.
- **Integration Issues**: Test each component independently before full integration.
